先看下面的泳道图：模型的两条写入边都停在草稿表；到 orders 的那条线，起点在「应用层」这一行。

三条链，一条边界

横轴是时间，纵轴是角色。写链由模型驱动，止于草稿；决议链由买家的 HTTP 动作驱动，是订单唯一的来源；取消链同样两步，中间态不动订单。

三个状态机

终态不能再确认。草稿的 superseded 不是买家动作，是「又建了一份新草稿」的副作用；取消请求的 superseded 同理。

草稿 draft pending →confirmed应用层确认（同事务插单） →cancelled作废（无副作用，无需二次确认） →superseded又建了一份新草稿
订单 order created →cancelled取消请求被买家确认（没有别的入口）
取消 cancel pending →confirmed买家确认（订单同事务置 cancelled） →withdrawn撤回（订单不动） →superseded又发起了一条新请求
应用层动作前置同一事务里的迁移幂等 / 错误
confirm_draft 买家匹配；草稿 pending 草稿 → confirmed；插 orders；写 2 条事件 已 confirmed 返回原订单（idempotent=true）；404 / 409
cancel_draft 买家匹配；草稿 pending 草稿 → cancelled；写事件 已 cancelled 返回成功；404 / 409
request_cancellation 买家匹配；订单 created 旧 pending → superseded；插新 pending 先查 (buyer, key)，命中即返回；404 / 409
confirm_cancellation 买家匹配；看最新一条请求 请求 → confirmed；订单 → cancelled；写 2 条事件 已完成后返回同一结果；404 / 409
withdraw_cancellation 买家匹配；看最新一条请求 请求 → withdrawn；订单不动 已 withdrawn 返回成功；404 / 409（没有请求也是 409）

    草稿价是下单时的快照。确认时不再比价——这是买家明确划掉的范围；另一个会话的观测也读不到，证据按会话隔离。

    保留期。默认 30 天（evidence_retention_days）：启动时清理一次，之后每天第一次写入时惰性清理。上个月看到的价格，不是今天下单的证据。S9 子 Agent 没有买家身份，所以它的 product_search 不写这张表。

    失败落在哪

    交易失败不该毁掉整轮对话。参数错误、证据缺失是模型可以纠正的事，用 ok=false 回给它；只有存储故障才是 ERROR。

    参数 / 证据不合法 SUCCESS + ok=false

    空 items、数量 0、重复 SKU、没检索过的 SKU、类型写错——都返回机器可读的 error，模型看到原因继续对话，不触发整轮 502。

    框架不校验 input_schema 工具体自己兜底

    AgentScope 的 FunctionTool.call 只广告 schema，不校验；ValidationError 逃出函数体就会变成 ERROR 工具块。所以参数归一化整段包在 try/except 里。

    存储故障 ERROR → 本轮 502

    这是唯一允许升级成 ERROR 的交易失败：数据库写不进去时，没有可纠正的语义，只能让本轮失败。

    HTTP 映射 404 / 409 / 503

    找不到（含非本人）→ 404；状态不允许 → 409 并带 current_status；订单服务未配置 → 503。不区分「不存在」和「不是你的」，避免泄露。
