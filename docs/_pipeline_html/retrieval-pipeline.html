上游：向量与过滤条件从哪里来

回答两个前置问题：向量由谁产生、过滤条件由谁填进 spec。

向量从哪里来？ 已实现

向量不是我们算的——由外部 embedding 模型（transformer 神经网络）通过 HTTP 接口返回。项目里的 OpenAIEmbedder 只负责发起请求：

POST {openai_base_url}/embeddings Authorization: Bearer <api_key> {"model": "text-embedding-3-small", "input": ["养猫 轻便 吸尘器", "…"]} → 返回 data[].embedding（每段文本一个固定维度浮点向量）

配置：openai_base_url / openai_api_key / openai_embedding_model（默认 text-embedding-3-small）。

本演示的 FakeEmbedder 是它的离线替身：字符频率计数 + 归一化，确定性、不联网，仅用于测试和这张图。

过滤条件从哪里来？ 未实现

过滤条件来自 ProductSearchSpec；但「自然语言 → 结构化 spec」这一步目前还没写。完整链路应是：

① 意图 / 槽位提取（LLM 解析自然语言）—— 未实现
"2000元以内、轻一点、养猫、吸尘器" → 拆成 spec 字段
↓
② 检索（已实现 QdrantProductSearch）
ProductSearchSpec(category=家用电器, price_max=2000, weight_max=1.5, currency=CNY, excluded=["过敏原"])

槽位映射："2000元以内" → price_max=2000、"轻一点" → weight_max=1.5、"吸尘器" → category=家用电器、"养猫" → query_text 语义。

在演示与现有代码里，spec 都是手工构造的；① 是下一步要做的事——一个 LLM 结构化提取调用，之后可挂成 AgentScope 工具。

向量何时算、在哪里调用

商品向量预计算、查询向量实时算——两个时机，两处调用，都走同一个 embed()。

商品向量
recreate(products)→ embed(texts) · 全部商品文本→ upsert 存进 Qdrant
预计算 · 之后不重算
查询向量
search(query)→ embed([query_text]) · 单条查询→ 与库中向量比相似度
实时 · 每次请求
# 商品向量 — 索引阶段（recreate 里，批量） qdrant_indexer.py:44 vectors = self._embedder.embed(texts) # 查询向量 — 查询阶段（search 里，单条） qdrant_search.py:64 vector = self._embedder.embed([query_text])[0]

仅测试调用目前 尚未接进运行中的 FastAPI：启动时建索引、查询路由都还没接线。
