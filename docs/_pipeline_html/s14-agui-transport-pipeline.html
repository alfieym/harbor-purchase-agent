四个结局

任何一条 run 的持久日志，最后一条一定是 RUN_FINISHED 或 RUN_ERROR——包括被进程重启打断的那些。

场景日志的最后status谁写的
成功STATE_SNAPSHOT → RUN_FINISHEDfinished与终态同事务
失败MESSAGE_END → RUN_ERROR(code)failed兜底 except，异常只进日志
取消快照(cancelled) → RUN_FINISHEDcancelledCancelledError 分支
重启RUN_ERROR(server_restarted)interrupted启动时扫遗留的 running
四个端点：POST /agui/runs 返回 202 · GET /agui/runs/{id}/events 重放再跟随 · POST /agui/runs/{id}/cancel 只取消一次 · GET /agui/runs/{id} 恢复前先问它。
失败只有一个 code 表：MODEL_TIMEOUT · MODEL_FAILED · TOOL_FAILED · NO_STRUCTURED_OUTPUT · CONTEXT_CAPACITY，兜底 TURN_FAILED。原始异常文本不出网关。

前端：一套 reducer，两种来源

实时流和刷新回放走的是同一个函数，区别只是 after 从 0 开始还是从 lastSeq 开始。

两条前端规则

seq 是幂等键

重连时重放与实时会重叠，丢掉 seq ≤ lastSeq 就够了，不需要去重表。没有编号的帧直接报错——它无法被幂等地应用。

卡片只来自快照

文本给人读，结构给程序读。商品卡只取 STATE_SNAPSHOT 里的 cards，不从中文里正则抠价格——那会在第一次改措辞时静默失效。

一个刻意的取舍：叙述文字按「模型调用」为单位冲出去，不是逐字实时。结构化输出那次调用必须扣下文本——那是没经过护栏的答案。所以过程文字成段到达、终版答案最后落定。docs/superpowers/specs 里「不做 token 级流式」这条已过期，以 S14-1 的实现为准。
